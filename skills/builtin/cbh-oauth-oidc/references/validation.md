# OAuth / OIDC 对照和案例

| 检查点 | 对照方法 | 应核对的结果 |
|---|---|---|
| Redirect URI | 正常注册地址对比一个经过授权、可观察的替代地址。记录原始参数、服务端解析结果与浏览器实际落点。 | 测试授权材料是否到达替代接收端。 [pixiv 公开报告](https://hackerone.com/reports/1861974) |
| State 与绑定 | 各自创建两个测试会话，交换回调事务并与正常回调比较。 | 应用是否在错误会话中建立身份或完成绑定。 |
| PKCE | 先确认正常交换可成功，再用新事务测试 verifier 与 challenge 不匹配。 | 令牌端是否签发可用令牌。缺少前端字段不足以判定。 |
| OIDC nonce | 用另一受控事务的返回材料做对照。 | 客户端是否接受跨事务 ID token，并将其用于登录。 |
| Issuer / Audience | 在已授权的两个客户端或资源中交叉使用测试令牌。 | 最终 API 或会话是否接受受众或签发方不匹配的令牌。 |

只在能隔离变量时测试路径规范化、域名边界或重定向链。先记首跳，只有后续地址也在授权范围内才跟随。
