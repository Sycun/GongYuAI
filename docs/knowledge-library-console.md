# 「知识与经验」首版控制台接入与验收设计

控制台已接入范围选择、关键词和混合检索、向量服务设置、索引进度、重试与重建。本文还列出后续完整导入和报告界面的设计与验收步骤。接口详情见[控制面契约](./knowledge-library-api.md)，实际模型切换结果见[脱敏验收记录](./evidence/knowledge-library/siliconflow-acceptance.json)。

## 一条操作路径

以委托 A 的报告为例。操作员从报告进入参考资料库，导入 SapperLens §6.4，找到写有“换任”的段落，将其引用为“独立分析从运行记录中观察到一次负责人换班”。读者在报告的「参考资料」中查看该段、所支持的表述、本地版本和校验值。以后资料库已有 v2，旧报告仍按引用从任务侧封存件读取 v1。

「知识与经验」首版开放**参考资料**。**项目经验**显示 P8 规划说明；已确认经验的跨项目复用另行交付。R-017 的归属、签收与撤回仍在**任务 History** 中复核。引用文章说明采用某种复核方法的理由，不能替代该任务的收件凭据。[三类记录的职责](./memory-layer.md#knowledge-library)

资料页由范围选择、检索框、结果列表和段落详情组成。在手机上，详情可全宽打开，返回列表时保留同一范围的关键词。全局入口允许先选资料，再选报告任务。确定目标任务后，重新在其范围内读取所选版本和段落，成功才开放提交。侧栏聊天项目名是浏览器本地分组，委托以服务端任务的 `engagementId` 为准。

## 操作与接口

| 操作 | 控制台请求 | 用户能判断什么 |
| --- | --- | --- |
| 预览和导入 | 先 `POST /knowledge/preview`，确认后 `POST /knowledge/materials`。文本以 UTF-8 处理，PDF 传文件字节的 Base64。预览、确认使用同一份输入。修改正文或范围后重新确认。 | 看见发布者、原始链接、原文／摘录／编辑导读、上游版本、章节和写入范围。写入时显式选择共享或一个委托。201 显示新版本，200 且 `reused` 显示已有版本。只有链接或正文提取为空时显示「待补正文」，不能生成段落引用。 |
| 搜索与读段 | 在同一上下文中读取 `/knowledge/summary`、`/knowledge/search`、资料版本详情及 `…/section?locator=…`。中文、§ 和页码按查询参数编码，原样保存服务端定位。 | 区分命中资料数、段落数及截断。按 `matchedFields`、`tagOnly` 展示命中原因。仅标题或标签命中的用户先打开资料主动选段，结果附带的首段定位只用于导航。 |
| 引用到任务 | `POST /tasks/:id/citations` 提交 `materialId`、`versionId`、`locator`、`claim`。成功后用服务端返回的引用 ID 刷新清单及报告。提交中禁用重复点击；遇到不确定回执先查清单。 | 每条引用列出“这段支持报告里的哪句话”。同一任务、版本、定位和表述重放时清单只保留一条。终态任务的报告会重新生成。 |
| 版本更新、回读和导出 | 同一来源、同一范围导入修订正文。停用指定旧版本时显示目标版号并记录原因。报告调用 `GET /tasks/:id/citations/:citationId/resolve`，下载服务端 `GET /tasks/:id/report-export` 返回的 JSON 包。 | 默认检索给有效版。旧引用同时显示「已停用」和复验结果。从 `task-seal` 复验成功后才展示旧段落；失败时显示原因和可用校验值。导出保留服务端的版本、报告与快照字节，可离线复算。 |

范围摘要取自服务端返回的 `scope`。详情和写入响应未带顶层 `scope` 时，以当前已确认的范围和返回的资料归属核对。当前导入端点以请求体 `scope` 决定写入位置，因此从 A 切到 B 的未提交导入须重新选定目标。若接线提供任务锚定的导入，还须在服务端校验任务与写入的专属范围一致。网络回执返回时只更新发起请求的上下文。[路由实现](../packages/control-plane/src/knowledge-api.ts) · [共享类型](../packages/contracts/src/knowledge.ts)

切换任务或委托时立即清空旧结果、计数、段落、导入预览、引用草稿和导出链接。取消旧请求并丢弃过期响应。所有查询、详情和停用请求都带同一任务上下文。受范围保护的单资源 404 统一显示「资料不存在或当前范围不可见」；409 提示重新核对任务与委托，保持原任务。现有通用 `probe` 将 404 分类为「未注册」，知识库页面需按已注册路由的业务语义展示。[控制台请求封装](../apps/console/src/api.ts)

## 向量化设置（本地 / 云端）

「参考资料 → 向量化设置」抽屉里选**本地服务**或**云端服务**。两套配置分别保存服务地址、模型 ID、密钥环境变量与密钥，切回来恢复原配置；密钥只显示掩码，明文不回浏览器。抽屉每次打开都重新读服务端配置，避免用旧草稿覆盖另一套。

页面必须讲清服务商会收到什么：**待索引资料的正文片段（含标题路径）与语义检索的查询文本**。原文、版本、向量索引与报告快照始终留在本地，云端只负责计算 embedding。

| 操作 | 控制台请求 | 用户能判断什么 |
| --- | --- | --- |
| 选服务商并保存 | `PUT /settings/knowledge-embedding`，一次带上 `provider`、`local`、`cloud`、`cloudEngagements` | 共享资料跟工作区选定的服务；委托专属资料默认本地，只有在「允许云端处理的委托」里明确列出的委托才可发往云端。 |
| 测试连接 | `POST /settings/knowledge-embedding/test`，可带未保存的草稿 | 显示模型 ID 与**实测维度**、耗时。后端只发固定合成短句，不触发重建；失败时原样显示上游状态码与错误。 |
| 重建 / 重试 | `POST /knowledge/index/rebuild`、`…/retry` | 202 且 `versions`/`queued` 非空才是「已排队」；空数组显示「没有需要重试的资料」。按 `index.services` 分服务展示模型、维度、已索引片段与是否获授权。 |

`index.blockedChunks > 0` 时页面要说明：这些片段属于未获授权的服务，本次不参与语义召回，也不会把查询文本发给该服务。**停用再启用同一模型**后状态是 `pending`、维度为空，单击重试即恢复 `ready`，不得靠整库重建绕过。

## 用这次收集的文章验收

执行模型在单独的验收数据根中准备两个不同委托 A、B，各有一个可打开报告的任务。通过正常控制台页面导入、检索、引用与下载，浏览器可用自动化操作。已有接口记录用作对照，页面展示的静态样例继续用于讲解。

| 材料 | 在页面中导入什么 | 用来判定什么 |
| --- | --- | --- |
| 女娲底座 README、SapperLens §6.4、本项目六批交接实验 | 分别选 History 说明、「状态与连续性」、「六批、五次交接」原文段落。统一加「负责人换班」标签，保留各自发布者、链接和定位。 | 三份材料分别是上游作者设计、独立运行观察、本项目合成实验。基准原文搜完整词是标签命中，另搜「换任」和「换班 54/60」验证正文字面命中。 |
| DeepSeek 原型领域模型、DeepSeekAgent.io 指南、MacOpenClaw 解读、本项目 R-017 补证用例 | 各自作为资料导入，原型选 Ticket 等术语所在段落，用例选「报告交付后收到更正凭据」。两篇解读分别登记发布者和原始链接，导入说明注明其共同上游。 | 搜「更正回函」能分清工作项定义、两篇同源解读和本项目实际验收。仅有链接的文章可登记为待补正文，其段落导入与引用验收继续标为待办。 |
| Anthropic 的长程 Agent 文章 | 选一段讲接班后复核已有工作的方法，记录标题、作者、原始链接与定位。需要中文导读时另建 `editorial` 记录。 | 搜约定的「会话接手」标签，分别打开作者摘录和中文导读，引用能回到选中的那一版。 |

材料来源与链接见 [P8 首批清单](./memory-layer.md#knowledge-library)。后端记录归档了三份上游原稿、来源提交及五份已导入摘录的哈希。可按记录中的相同段落复用这些字节。记录以外的文章在本次浏览器运行中单列实际取得的来源、段落和版本。导读样例与尚无正文的条目各自单列。[文章验收脚本](../scripts/knowledge-acceptance.ts) · [归档来源与校验值](./evidence/knowledge-library/knowledge-1795404972071/acceptance-record.md)

### 浏览器签收单

以下各行初始状态均为**待执行**。使用本轮生成的任务、资料、版本和引用 ID 关联证据。

| 场景 | 操作与通过条件 |
| --- | --- |
| 1 · 导航与导入 | 从工作区和 A 的报告分别进入资料库，确认共享视图与任务视图显示正确。先预览再取消，计数不变；随后确认导入，刷新仍可查。重放同一来源和内容时返回同一版本。抽查一个链接条目只显示「待补正文」。 |
| 2 · 检索与引用 | 运行上表的查询，保存各条材料实际的命中字段。打开 SapperLens `§6.4` 的正文，给 A 的报告添加关于一次负责人换班的表述。刷新报告能看到引用，重复提交相同表述后仍只有一条。 |
| 3 · 封存首份报告 | 在资料 v1 时从 A 的报告页下载并保留原始导出包 E1。记录非空的报告正文及其 SHA-256、引用 ID、版本 ID、定位、版本全文的 SHA-256 和选中段落。抽取报告时使用包含该引用的终态任务。 |
| 4 · 更新后回读原版 | 从控制台用同一来源导入本地验收修订 v2，使 `§6.4` 有可辨别的文字变化，并标明是验收修订。停用 v1。默认检索应看到 v2；关掉旧标签页、重开原任务并按引用 ID 回读，应看到已停用的 v1、原段落和 `verified`。任务侧复算哈希应等于步骤 3 的版本哈希且不同于 v2。 |
| 5 · 离线旧报告 | 在无法访问上游且控制面重新启动后复做回读，保留回环服务可达、上游不可达的对照。另把 **更新前已下载的 E1** 放进独立目录，在无服务的环境中取出报告与快照，分别复算报告 UTF-8 和解码后快照字节的 SHA-256，按定位读到同一旧段。这分别验证了服务重启后的回读和已交付文件的自足性。 |
| 6 · 双向委托隔离 | 用共享资料 S 和 A、B 各自的专属资料，给专属样本各加唯一标记。A 的列表、摘要计数、搜索、直接详情、选段及下载包只含 S 和 A 的资料，B 方向对称验证。用另一委托的资料 ID 尝试打开或引用，统一 404；声明上下文与任务归属冲突时 409。失败后两份报告及引用清单均不新增记录。 |
| 7 · 切换与失败状态 | 延迟 A 的搜索或详情响应，在其返回前切到 B。迟到响应、浏览器后退、刷新和旧抽屉都不能把 A 的资料显示到 B。使用一次性验收副本内缺失或损坏的任务侧密封件验证「无法复验」，页面不给出正文，也不自动换用当前有效版。 |
| 8 · 服务互切与重试 | 本地 → 云端 → 本地各完成一次当前范围重建与一次语义检索，记录服务、模型、维度与索引指纹；刷新后两套配置仍在、凭据互不串用。停用 → 重新启用 → 只点重试，记录实际入队数与最终 `ready`；再验服务暂时不可用、恢复后仅靠重试成功，以及无任务可重试时的页面提示。A、B 两委托加一份共享资料，用可观测测试服务核对未允许范围内零次云端请求。 |

隔离检查要打开导出包本身，核对报告 Markdown、引用元数据、段落和解码后的快照均不含对方的唯一标记或资料 ID。共享资料在两边均可读是必要的正例。单操作者模式可以选择声明的委托，`userLevelPermissionVerified` 当前为 `false`。本项签收的是服务端任务范围和前端切换行为，用户身份及多租户鉴权仍需另行设计。[已有双向隔离用例](../packages/control-plane/src/knowledge-isolation.test.ts)
