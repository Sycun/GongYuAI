# 数据飞轮（Data Flywheel，P9 提案）

2026-11-22 起草。状态：**提案，未动工**。目标：**让 Agent 越用越好用**——可测量、可审计、人受控的正反馈循环。  
配套：[memory-layer.md](./memory-layer.md)（P8）· [dev-handbook.md](./dev-handbook.md) · [evidence-review.md](./evidence-review.md) · [absorb-sapper-v2-nuwa.md](./absorb-sapper-v2-nuwa.md)

## 结论（先读这四句）

1. **飞轮转的是 harness 与知识，不是模型权重**：不做微调/RL——「价值在 harness，模型可换」（sapper 同信仰）。越用越好用 = 经验更准、技能更熟、调度更省、纪律更硬。
2. **原料管道已埋好大半**：History events（tool_gate/relay/超时/FSM）、execution-trace（每步工具/token/相位/shell 调用）、用量记账（runUsage/usage）、复核/覆盖链、finding 状态迁移——每个任务自动留下结构化数据，飞轮不需要新埋点，需要的是**统一导出 + 评测 + 提案闭环**。
3. **飞轮已经手动转过两圈**（可行性证据）：六批实验发现交付格式违规 → 结构化交接字段（notice/subject/scope）→ 两批回归 57→59；技能路由固定用例 2/8→8/8。P9 做的是把「评测→提案」段自动化，**人审与差分验证保留**。
4. **质量闸是飞轮的一部分，不是外挂**：无人审不晋升、无反例不沉淀、无差分不默认、holdout 不调参——防止垃圾飞轮与指标刷分（Goodhart）。

## 一、五环飞轮

```text
        ┌────────────────────────────────────────────┐
        ▼                                            │
① 采集 ──▶ ② 评测 ──▶ ③ 蒸馏 ──▶ ④ 改进 ──▶ ⑤ 验证 ─┘
（任务自动留痕）（记分卡+趋势）（经验/技能/参数提案）（人审落地）（同预算差分+holdout）
        每一环都过中心质量闸：人审 · 溯源 · 差分 · holdout
```

### ① 采集（大半已有）

| 数据 | 来源 | 状态 |
| --- | --- | --- |
| 工具闸判定（允许/拒绝/原因） | `tool_gate` events | ✅ |
| 每步工具/token/相位/shell 调用 | execution-trace（saveExecutionStep） | ✅ |
| 用量（本轮增量/累计） | usage 记账 + worker-status | ✅ |

| 超时/部分 Fact/Intent 终态 | explore_timeout_conclude / FSM events | ✅ |
| 人工复核/撤回/覆盖判定 | fact_reviews / coverage_reviews | ✅ |
| finding 状态迁移与证据 | findings 表（P6 E1） | 🔨 并行会话落地中 |
| **统一导出**：任务记分卡原料包 | 上述聚合为一个只读导出 | ❌ F1 要建 |

### ② 评测（飞轮的仪表盘，部分已有）

- **任务记分卡**：目标通过率、finding precision（以人工复核为底稿）、token/墙钟成本、交接损失（换班前后字段保持）、超时率、幻影工具调用数、技能路由命中。
- **纵向趋势**：按任务批次聚合，看「越用越好」是否真实发生（复用率↑、成本↓、precision↑）。
- **基准回归**（已有基建复用）：TSecBench 子集差分、finding-bench（P6 E6）、offline-review 台账夹具、skill-routing 固定用例、coverage-compare 盲评。
- 纪律不变：**只报相对差分、协议先冻结、development/holdout 分组**（evidence-review 既有口径）。

### ③ 蒸馏（P8 联动 + 新增参数提案）

- 经验/打法/反例/工具遗产 → 记忆图 draft（P8 M1/M3）。
- **新增：harness 参数提案**——跨任务统计聚合产出 draft 建议：Relay 阈值、扇出硬顶、soft-pace 节奏、模型路由（P7）、Observe 注入上限 N。每条提案**必须附证据链接**（记分卡差分 + 源任务），无证据不提案。
- **新增：prompt 纪律补丁提案**——从重复失败模式归纳（如格式违规、幻影调用、撤回对象错位），产 draft 补丁文本 + 复现用例。

### ④ 改进（执行器，全部人审）

| 执行器 | 动作 | 审批 |
| --- | --- | --- |
| 记忆注入 | confirmed Lesson 按 MatchKey 进新任务 | 复核 confirmed 才可注入（P8） |
| 技能演进 | Playbook 固化 Skill 草案 + 路由触发词更新 | 人审写盘 |
| harness 参数 | 配置变更（阈值/硬顶/路由） | 人批准 + 配置版本化可回滚 |
| prompt 纪律 | 系统提示/board-policy 补丁 | 人审 + 回归用例 |
| 工具遗产 | 登记脚本进入可用工具面 | 人审（未审不得执行） |

### ⑤ 验证（晋升闸）

- 每项改进先过**离线夹具差分**（确定性桩，零网络），再按需要过真平台子集同预算差分。
- **holdout 只验不调**：留出集成绩只用于晋升判定，不得反向调参。
- 通过 → 晋升默认；不通过 → 提案归档留痕（append-only）；已晋升项出问题 → 配置回滚 / Lesson retracted。

## 二、质量闸（防垃圾飞轮）

1. **人审闸**：draft 永不自动 confirmed / 自动晋升默认。
2. **溯源闸**：无源不记忆、无证据不提案（同 P8「无源不记忆」）。
3. **反例驱动降级**：注入失效 → Counterexample 追加 → reuseCount 权重下降；stack/版本漂移 → 时效衰减标记。
4. **坏事实防毒化**：注入携带复核状态与反例；源被撤回 → 记忆节点标「依据已撤回，待复核」（sapper 单字符串事实图「一错全错」教训的结构化解法）。
5. **指标对齐**：目标函数是攻击面经营 + 可审计 finding（board-policy 既定），**不是 flag 数**——防飞轮朝刷分优化。
6. **holdout 隔离**：防对自家历史过拟合；盲评底稿在平台判断之前封存（coverage-compare 既有流程）。
7. **数据不出本机**：飞轮全部在 data-root 内运转；导出交付沿用证据访问约定。

## 三、控制台飞轮看板

- **趋势页**：成功率 / 成本 / 复用率 / 路由命中 / precision 按批次曲线；飞轮健康度（trace 覆盖率、复核积压、holdout 计划）。
- **改进提案收件箱**：draft 提案列表（记忆/技能/参数/prompt/工具五类），每条带证据链接与预期收益；操作员一键批准/驳回（写审计事件）。
- **晋升与回滚记录**：配置版本链 + 每项默认变更的差分依据——「为什么变好了」可复盘。
- 纪律：控制台只读投影 + 审批写 API，不发明第二套状态。

| 刀 | 内容 | 验收 |

依赖：P8 M1（记忆库）、P6 E1（precision 指标原料）；P7 模型路由是飞轮执行器之一。**排序已定：F1 先做**（无依赖，为 E1/P7/P8 差分供仪表盘）；P7 差分统计口径按 [absorb-eval-methodology.md](./absorb-eval-methodology.md) 执行。

## 五、明确不做

- 模型微调 / RL / 权重训练（模型可换，价值在 harness）。
- 自动晋升默认、自动写 Skill、自动执行遗产脚本。
- 用 holdout 调参、用 flag 数当目标函数、无证据提案。
- 飞轮数据出本机、跨用户共享（单用户平台；多租户是另一个授权决策）。
- 把「越用越好用」当营销断言——只报记分卡差分，趋势不显著就如实说未显著。

## 六、北极星扩展

> Harness 让任务活着；History 让路径可信；Evidence 让完成可复核；Relay 让上下文可换班；**Flywheel 让使用变成进化——每次任务都留下数据，每份数据都过闸变成经验，每条经验都经差分验证才成为默认。**
