# 第九轮未验证清单（给项目所有者）

> 只列**没有证据**的部分；工程已走通的项目见 [delivery-record.md](./delivery-record.md) §0 与 `docs/evidence/r9/`。
> 三类分开：A 工程缺项、B 缺真实供应商环境、C 缺真实生产材料。任一项缺失时，对外只能写「真实生产效果待验证」。

## A. 工程缺项（本轮没做或只做了一半）

| 项 | 现状 | 影响 | 下一步 |
| --- | --- | --- | --- |
| 前端页面 | 本轮只交 JSON API 与契约（[api-contract-r9.md](./api-contract-r9.md)）；控制台未接四图/矩阵/记忆/作业/交接面板 | 操作员暂时只能走 CLI/HTTP 看新能力 | 由独立前端任务按契约实现；后端字段已稳定 |
| Worker 侧接入 | 作业/求助/回忆注入主要落在控制面与 History；`pi-loop` 尚未在 Explore 中自动调用 `operator_consult`/`memory inject`/作业回流唤醒 | 自动长跑仍靠既有 Relay/Checkpoint；"模型主动求助"目前由操作员/验收脚本驱动 | 在 worker 工具面加 `operator_consult`、`job_submit`、`memory_read` 并补差分 |
| 真实模型调用 | 角色分层、模拟模型请求都是确定性模拟（`authenticity:"simulated"`） | 无法据此声称"规划者/复核者提升了判断正确率" | 取得可用模型配额后，用同一冻结材料跑单模型 vs 分层对照 |
| 供应商 key 池 / 真实 failover | 只有契约级 `planProviderAttempt` + 事件台账；`pi-loop` 仍是单 key、非 2xx 直接抛错 | 数日长跑遇 429/余额不足仍会中断 | 把 router 接进 `pi-loop` 的 chat 调用，补真实 429/5xx 演练 |
| 会话管理器 / 隧道 / 浏览器内核 | 未实现（只有作业与求助） | 拿 shell 之后的长链、pivot、登录态复用仍靠人工 | 按 P11 S1/S3 单独立项 |
| 凭据结构化（P6-E2） | 只做到"材料侧受控引用"（`secretRef` 不落明文）；无 Credential 表、无 `credential_record/session_close` | 跨 Worker 复用凭据仍靠 π 文本 | 与 worker 工具面一起做 |
| parser lane（P6-E3） | 只有 `parse-import` 作业对已导入材料做确定性摘要（行数/类型/SHA）；未接 nmap/nuclei/httpx 原始输出 | 工具输出仍不能自动变资产/finding | 先做 3 种 fixture 的旁路解析与 `parser=skip` |
| 速率/破坏性硬闸（P6-E4） | 未加 `rateLimit/timeWindow/roe/destructive` 契约 | 生产资产仍只有软节奏提示 | 与 RoE 一起在 AuthScope 扩展，默认仍不设硬顶 |
| 事件哈希链 / TSA（P12-D8） | 未做；报告版本与证据封存已有 | 法律级防篡改与可信时间戳仍缺 | 给 `events` 加 `prev_hash`，导出校验清单；TSA 另议 |
| 暂停停表 | 仍是原 `startedAt` 口径（暂停时长计入墙钟） | 预算墙钟读数偏高 | 需要 `pausedMs` 累计字段与预算口径变更 |
| 记忆控制台/蒸馏自动化 | 只有 API 与手动 `memory` 命令；终态自动候选清单未接 | 经验沉淀仍需人写 draft | P8 M3 |
| 评测夹具 | Finding 级指标与冻结/隔离已实现；没有 `examples/finding-bench/` 真夹具，验收用的是手写 `cases` | 指标可复算，但不能代表真实发现能力 | 需要人工底稿后再产夹具 |

## B. 缺真实供应商环境

| 需要的东西 | 为什么需要 | 没有它就不能声称 |
| --- | --- | --- |
| 至少两个可用 provider 的 key（含一个**获准接收客户材料**的备用） | 验证 429 退避、余额不足切换、外发受限阻塞 | "供应商韧性已生效" |
| 真实账单/用量回执 | 校准 `billing:"billed"` 与 `costVisible` | "成本下降/省钱"（本轮只记录"无账单"） |
| 一次真实 429 与一次余额不足 | 故障注入只是契约级 | "故障恢复后不重复记账"在真实链路上成立 |
| 真实模型配额 | 角色分层与单模型基线的同预算对照 | "规划者/复核者带来判断正确率提升" |

本轮如实标注：**真实供应商表现待验证**。验收中所有模型相关条目均为 `simulated`、`billing:"none"`。

## D. 结论口径（对外可直接用）

- 工程侧：**已走通**——委托边界、持久资料作业（含进程中断→unknown→重试→回流）、24h 求助、跨班交接、材料语义与撤回一致性、四图 API、记忆生命周期与客户隔离、冻结评测/提案晋升回退、角色权限与供应商故障契约。证据：`docs/evidence/r9/r9-ops-1795364124610/`（67/67）、`docs/evidence/r9/r9-flywheel-1795364131957/`（57/57）。
- 生产侧：**真实生产效果待验证**——缺脱敏真实委托、客户书面许可、独立人工底稿；缺真实供应商环境。
- 不得转述为："系统已经在真实客户环境验证有效"、"模型路由已证明更省钱"、"覆盖矩阵已证明发现率提升"。
