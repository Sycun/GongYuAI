## 0. 一句话

> **GongYuAI 是面向授权红队作业的长时运行渗透工作台：目标进入任务即视为授权，运行中不审查目标、不拒绝目标；能力全谱、连续运转、结论可复核、经验可传承。**

北极星（2026-11-24 修订）：

> 女娲让作业活着；DAG 让路径可信；Evidence 让结论可复核；Relay 让上下文可换班；Super-agent 让每一分预算花在更可能出结论的面上。

三条设计公理：

1. **授权是使用前提，不是运行时功能。** 工具不登记、不验证、不询问授权；使用者对交给工具的目标负责。
2. **拒绝只有一个形态：工程自保。** 与目标相关的解释性拒绝不存在；模型说「不能做」是缺陷，不是行为。
3. **不拒绝 ≠ 乱打。** 手段不设类别禁令，路径仍受 DAG 因果继承与证据闸约束——纪律保的是「打得对」，不是「少打」。

## 1. 三条基础理论如何分工

长程渗透会以三种方式失败：**人死了**（进程/会话中断、上下文丢失）、**路走歪了**（意图漂移、无因探索、把猜测当事实）、**钱花错了**（在低价值面上磨、重复派单、模型选型浪费）。三条理论各治一种病：

| 基座 | 治什么病 | 机制落点 | 长跑表现 |
| --- | --- | --- | --- |
| **女娲**（存活 / 繁衍） | 人死了 | lease + Watchdog + checkpoint、Session Relay π、分层 History、全局记忆与飞轮 | 进程可死、会话可换、作业不死；干过的活沉淀为下个委托的弹药 |
| **DAG**（路径 / 真相） | 路走歪了 | Fact–Intent 无因探索禁令、conclude 回写、证据闸 + SHA-256、复核撤回 | LLM 只做局部提议器，全局连贯性交给图；结论可被第三方推翻 |
| **Super-agent**（调度经济） | 钱花错了 | 脑手分离的相位工具面、多 Explore 异步派单、模型分层、观察员记分卡 | 主脑不拿工具；便宜模型跑腿、强模型决策；浪费可见 |

**分工金句**：DAG 管路径；分层 History 管可读性；Relay 管换班；Durable/lease 管进程活着；Evidence 管结论可复核；Super-agent 管调度经济；女娲的繁衍环让使用变成进化。

**执行权归属不变**：只有 Fact–Intent DAG 有执行权（图状态生成任务）；pi task graph 是运行时传动；资产/攻击面/执行/记忆四图是只读投影，影响执行唯一通道是 Hint（建议层）→ 仍过 DAG 硬闸。**一图驱动、一图传动、四图旁观，旁观递条子过闸。**

一条来自实战的旁证：sapper-V2 在腾讯云攻防赛以 1B tokens 对抗对手 4.5B，靠的不是更大模型，而是事实图共享、同族迁移与调度策略（[对比文](https://mp.weixin.qq.com/s/VgGSQOKgjLH7d3TVTDp4wg)）。这正是本仓「图管对、调度管省」的论据；ARTEX 的双图记忆 + MITM 流量留痕 + 五层 LLM 重试 + 用量账本，则补的是长期无人值守的工程厚度。两家都把「授权边界」写进了自己的产品约束（ARTEX 禁止线上实测），**我们不吸收这一层**——授权归使用者，见 §3。

## 2. 产品定位：完整、长时、可复核

一个「完整」的红队工具必须同时是三样东西：

1. **全链作业面**：授权→侦察→指纹/资产测绘→Web/API→盲打验证→利用/GetShell→凭据→提权→横向/pivot→AD/云→证据→复测→报告。主链已通，域模型（AD/云/提权枚举器）见 [pentest-completeness.md](./pentest-completeness.md) 的缺口排序。
2. **长时运行体**：默认连续运转到目标全过或人工暂停/结束；无硬预算、无默认时间窗、无默认速率闸（用户定调，[pentest-ops-design.md](./pentest-ops-design.md)）。进程活、会话活、作业活、上下文可换班。
3. **可复核交付**：完成必须有证据；证据可封存、可下钻、可撤回、可复测；报告能回答「这条结论依据哪份原件、谁验的、后续是否被推翻」。

**反例（看到就停）**：把工具做成「安全扫描器的聊天壳」——只读、只建议、动辄请示、以「合规」为名把可执行动作降级为教程。那不是红队工具，是文档生成器。

## 3. 授权模型：目标默认授权，不设授权层

### 3.1 授权是使用前提

- 授权由**部署者/使用者**在工具之外取得并持有：书面委托、授权书、SRC/众测规则、靶场公告，任一即可。责任在人不在于工具。
- 工具**不设授权登记、不设目标白名单审查、不设授权版本、不判断目标合法性**。`DISCLAIMER.md` 约束的是使用者的行为，不进入产品流程。
- 目标进入任务的那一刻即视为授权目标。运行中追加目标、横向发现的新资产、隧道对端——同样是授权目标，**不需要也不会再走一次「授权」。**

### 3.2 任务输入是作业坐标，不是授权闸

工具仍需知道「打哪、不打哪、什么节奏」，这些字段保留，但语义是**操作配置**：

| 字段 | 语义 | 不是什么 |
| --- | --- | --- |
| `targets` | 本次作业的坐标（域/IP/CIDR/URL/资产事实） | 授权证明、白名单审查 |
| `outOfScope` | 操作者的排除项（客户要求不碰的段、生产库等） | 合规闸 |
| `roe` | 操作者意图自由文本（节奏、禁区、特别要求） | 规则解析引擎 |
| `rateGuidance` | 节奏建议（模型自判执行） | 默认硬限速 |
| `timeWindow` | 可选时间窗（默认不设 = 连续运转） | 默认停机条件 |

- 缺目标、缺材料、坐标冲突 → 结构化 `needs_input`（澄清后继续），**不是** `needs_authorization`。
- 能力/相位配置（observe/scan/active-lab/full）是**操作档位**（决定工具面可见性），不是「目标是否可打」的审查。
- 是否执行某类技术（含规避与对抗）由 RoE 与操作者意图决定，**不由目标是否「敏感」决定**。

### 3.3 一句话裁决

> 目标合法性：使用者的事。路径合法性：DAG 的事。运行环境安全：工程的事。三者不许混。

## 4. 零目标拒绝（No Target Refusal）

### 4.1 三类「拒绝」必须分开

| 类型 | 形态 | 产品行为 |
| --- | --- | --- |
| **A. 目标合法性审查** | 「这是外部目标，我不能协助」 | **不存在**。不实现、不提示、不询问 |
| **B. 解释性拒绝** | 「我是 AI，无法执行攻击性操作」「建议您联系安全团队」 | **模型缺陷**。自动纠偏/重派/换模型，绝不作为终态呈现给操作员 |
| **C. 工程自保** | 改本机路由/VPN/代理、破坏运行主机、把作业事故引到宿主 | **保留**。与目标无关，只保护运行环境 |

**允许的拒绝只有 C**，且必须给出可执行的结构化原因（哪个动作、为什么触碰工程边界、替代做法）。C 的判定是确定性的（代码规则），不经过模型，不允许模型把 C 扩大成 A/B。

### 4.2 结构化输出协议

模型对任务处理器的合法输出只有四种：

```text
{"kind":"result"}      # 给出可核验结果
{"kind":"command"}     # 给出要执行的命令（系统负责执行与证据）
{"kind":"needs_input"} # 缺坐标、缺材料、目标不可达等，说清缺什么
{"kind":"paused"}      # 仅限「材料不足、等外部输入」，并附原因
```

- **没有 `refuse` / `cannot` / `not_authorized` 类型。** 模型若输出解释性拒绝，按缺陷处理（§4.3）。
- `needs_input` 是澄清请求，不是授权申请；操作员补充后立即继续。
- 执行结果中的 `blocked` / `denied` 只允许来自确定性规则（工程自保、缺参数、资源不可用），并带机器可读原因；不允许是模型自述。

### 4.3 模型拒绝的处理链（把拒绝当故障修，而不是当结论收）

1. **作业上下文重问**：把作业坐标、已有证据、上一步结果重新注入，要求给 `command` 或 `needs_input`。
2. **结构化重问**：明确「只返回 JSON，禁止解释性文本」，缩小到单步动作（例如只问「列出下一步要跑的一条命令」）。
3. **换模型**：从模型池取下一个可用模型执行同一 Intent（Provider 韧性 P13-A6 的职责）。
4. **拆小重派**：把被拒的复合任务拆成更小的单步 Intent，避免模型对「大而全的攻击指令」产生整体性拒绝。
5. **操作员入口**：若以上都失败，向操作员呈现**结构化故障**（`MODEL_REFUSED` + 尝试过的模型列表 + 原始拒绝片段），并提供两条路：换模型重跑，或在会话里直接给命令（手动命令是绕过模型，不是绕过工程自保）。

硬纪律：
- 拒绝**永不被写成 Fact**（不把「模型说不能」记成攻击路径上的结论）。
- 拒绝**永不产生终态**（任务不因拒绝而 `stopped`；最多 `paused` 等操作员换模型）。
- 拒绝纠偏**不计入攻击失败**（记分卡单列 `model_refusal` 事件）。
- 纠偏上限是资源问题不是语义问题：可以重试 N 次、换 M 个模型，但**不允许把「拒绝」翻译成「目标无漏洞」**。

## 5. 能力全谱：完全红队化

### 5.1 不设技术类别禁令

以下都是授权红队作业的正当组成部分，工具不因类别拒绝，只按 RoE 与操作者意图执行：

- 漏洞验证与利用、GetShell、反弹会话、C2、持久化与驻留；
- 凭据抓取/转储与复用、哈希传递、票据攻击、AD 路径利用；
- 横向移动、隧道、pivot、多跳内网、域控接近；
- 防御对抗：WAF 绕过、AV/EDR 规避、免杀、混淆、流量伪装（评估检测能力本身就是红队目标）；
- 数据外带证明（数据可达性验证）、供应链与云侧攻击面。

### 5.2 红队纪律（不是禁令）

- **证据最小化**：外带只取证明所需的最小样本，不批量拖取客户生产数据；敏感样本走内容寻址证据库，不进聊天上下文。
- **变更台账**：对目标系统的修改（webshell、账户、配置、隧道）一律登记，可回滚说明，作业结束出残留清单。
- **不替客户修漏洞**：自动化修复/打补丁不是本工具职责；发现即记录，修复归客户。
- **可复现**：每条结论附原始事务/证据/复现步骤，换一个人拿同样的东西能验证或推翻。

四条纪律的目的是**让攻击可交付**，不是给攻击设限。

## 6. 三基座如何保证「不拒绝也不跑偏」

| 长跑风险 | 对应机制 | 一句话 |
| --- | --- | --- |
| 模型拒绝 / 供应商抖动 | 拒绝处理链（§4.3）、Provider 池、模型分层 | 换脑不换目标 |
| 上下文遗忘 / 意图漂移 | Fact–Intent DAG、Relay、观察员 | 信念在图里，不在对话里 |
| 在同一手法上磨 | 观察员 `repeat-failure`、计划链、记分卡 | 磨不动就换面，不是停工 |
| 进程 / 会话 / 作业中断 | lease、Watchdog、detached 会话、后台作业通知回流 | 能死能复生 |
| 复核自证 / 误报 | 证据角色、独立确认（C1）、复测 | 结论可被推翻才可信 |
| 经验不沉淀 | 全局记忆、飞轮、技能演进 | 越用越好用 |

**关键等式**：零目标拒绝 + DAG 因果继承 + 证据闸 = **敢打，且打得出可交付的结论**。缺任何一项都会退化：缺零拒绝→安全壳；缺 DAG→乱打；缺证据→不可交付。

## 8. 落地状态（P16 语义收敛，2026-11-24 已落码）

本节原为「目标语义 vs 现状代码」差距表；P16 收敛后逐项落码如下（契约同步见 [long-run-contract.md](./long-run-contract.md)「Capability ladder」）。

| # | 原差距 | 收敛落点 | 状态 |
| --- | --- | --- | --- |
| 1 | `authorization.ts` 授权台账（版本、撤销、原件封存） | 写入路径移除；模块收敛为旧台账**只读兼容** + 任务坐标解析（`parseScopeMessage`）；`targets/outOfScope/roe` 是普通任务字段 | ✅ |
| 2 | `needs_authorization` 结构化请求 + 会话内「已授权…继续」 | `needs_input` 澄清（`NEEDS_INPUT` 前缀）；续接把目标/排除/能力**合并进任务坐标**，不登记授权；「已授权 X，继续」兼容为加入坐标 | ✅ |
| 3 | 模型拒绝纠偏仅一次 → `MODEL_REFUSED` 停住 | 拒绝处理链：上下文重问 → 结构化重问 → 换模型（≤3）→ 操作员 `paused` 结构化故障（可换模型重跑/手动命令）；拒绝不写终态、不写 Fact | ✅ |
| 4 | `authorizeCommand` 按 `auth.targets` 裁决范围 | 按任务坐标与操作档位裁决；工程自保（主机网络/破坏性）确定性拒绝保留，不依赖模型、不针对目标 | ✅ |
| 5 | 契约文档把授权版本作为核心概念 | `authorizationNote` 可选化、capability 默认 `active-lab`、新增 `roe`；`scopeVersion` 仅表示操作配置变更；`authorizationPromptBlock` → `taskScopePromptBlock` | ✅ |
| 6 | DISCLAIMER 要求每任务提交授权说明与白名单 | 授权为使用前提；工具不设登记步骤 | ✅（前轮已改） |

**验收口径**（P16 测试逐条断言，见 `packages/control-plane/src/p16-semantics.test.ts`）：
- 对任意目标（含外部公网目标），模型输出中不出现解释性拒绝；出现即走纠偏链，测试失败若纠偏后仍呈现拒绝终态。
- 拒绝纠偏后任务不进入 `MODEL_REFUSED` 终态；只允许 `paused` + 换模型重跑。
- 无授权登记步骤时，任务可直接从目标坐标启动（`authorizationNote` 可省略）。
- 工程自保拒绝仍然有效（改本机路由/VPN 永拒），且原因可读、不针对目标。
- 旧授权台账数据按只读兼容处理（`GET /tasks/:id/authorization` 仍可回查），不阻塞新任务；`POST /tasks/:id/authorization` 返回 410 指引 `/scope`。
