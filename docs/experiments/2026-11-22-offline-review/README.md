# 离线台账复核的真模型对照

2026 年 11 月 22 日，使用 DeepSeek API 返回的模型 `deepseek-flash`，对同一批 6 份合成台账各复核两次。**DAG 比 bare 多答对 1 个字段，多用 599 Token（2.4%）。DAG + Relay 比 DAG 少用 6,473 Token（25.7%），少答对 3 个字段。** 四份台账在所有组、两次重复中均满分；差异集中在撤回记录和旧账状态的判读。

## 准确率与用量

每份台账有 5 个标准答案，每组共 60 个字段、12 个题次。每个题次实际调用模型两次。输入 Token 包含缓存命中，两阶段输出均计入。表中百分比以未四舍五入的原数计算。

| 组别 | 字段正确率 | 整题全对 | 输入 Token | 输出 Token | 总 Token | 平均每题次 | 相对 bare |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| bare | 59/60（98.3%） | 11/12 | 21,526 | 3,085 | 24,611 | 2,051 | 基线 |
| DAG | 60/60（100%） | 12/12 | 22,320 | 2,890 | 25,210 | 2,101 | +599（+2.4%） |
| DAG + Relay | 57/60（95.0%） | 9/12 | 15,802 | 2,935 | 18,737 | 1,561 | −5,874（−23.9%） |

三组第一阶段的输入各为 **8,196 Token**。第二阶段的输入分别为 **13,330、14,124、7,606 Token**。换班后重新读取交接笔记、本批材料和 DAG 祖先，省去了重发整段第一批对话。DAG 与 DAG + Relay 的第二阶段输入相差 6,518 Token，两阶段输出合计相差 45 Token。由此可以定位节省发生在哪一步。

服务端记录的输入缓存命中分别为 **14,848、15,104、4,992 Token**。DAG + Relay 虽然总量最少，未命中缓存的输入却最多（10,810 Token）。本实验未取得账单，金额需按实际命中和未命中费率另算。

## 逐题配对

每格为两次重复合计的“正确字段数 / 10”和总 Token。R017 改编自项目原有的早期证据、纠错和缺签收验收；LEGACY、BYTES 延用历史断言与二进制附件回归的情境。另三题覆盖多级引用、目标范围和独立复核。

| 台账 | bare | DAG | DAG + Relay |
| --- | ---: | ---: | ---: |
| R017 收件与签收 | 10/10 · 5,886 | 10/10 · 5,840 | 9/10 · 3,770 |
| LEGACY 迁移旧账 | 9/10 · 3,403 | 10/10 · 3,540 | 8/10 · 2,681 |
| BYTES 二进制附件 | 10/10 · 3,432 | 10/10 · 3,796 | 10/10 · 3,070 |
| CHAIN 多级汇总 | 10/10 · 4,030 | 10/10 · 4,176 | 10/10 · 3,144 |
| SCOPE 分目标复核 | 10/10 · 3,198 | 10/10 · 3,294 | 10/10 · 2,686 |
| RECHECK 独立重核 | 10/10 · 4,662 | 10/10 · 4,564 | 10/10 · 3,386 |

- **撤回对象错位。** 第一次重复，Relay 组在 R017 和 LEGACY 都把“被撤回的记录”答成发布撤回意见的 F4。正确值分别是 F2、F3。两份交接笔记都提到了相应原记录，第二阶段的祖先索引也保留了它们，最终答案仍混淆了两个编号。
- **历史通过与当前可复验性混淆。** 第二次重复，bare 和 Relay 组都将 LEGACY 的历史目标状态填为 `unverified`。旧日志明确记为 `passed`；未知的是当时的证据版本和归属。两组在后两个字段均答对。

两轮字段得分依次为 bare **30、29**，DAG **30、30**，DAG + Relay **28、29**（每轮满分 30）。六份台账上 Relay 均节省 Token。准确率差距只来自两份台账，重复运行同一题不能增加独立样本数。这里的测量适用于两批文档的一次交接，尚不足以判断更长会话或其他模型上的排序。

## 实验条件与复算

题库、答案、提示和分组协议在首个正式请求之前已冻结。[实验开始时的提交](https://github.com/Sycun/GongYuAI/commit/db6a12c7dcd9b541135dbe22c04108972db217d8)

第一阶段三组使用逐字相同的材料、问题和工作笔记要求，各自实际生成笔记。第二阶段 bare 保留全文，DAG 在全文外补上项目 History 图中本批引用的早期祖先。Relay 组使用同一祖先索引，经项目 Session Relay 落盘再读回工作笔记，在新消息列表中完成复核。输入资料相同，进入模型上下文的表示和长度随组别变化。[冻结的实验协议](../../../examples/offline-review/README.md) · [题库与答案](../../../examples/offline-review/cases.json)

三组统一使用 temperature 0、关闭 thinking、JSON 输出，每题次总上限 **16,384 Token**，两次调用的输出上限分别为 384 和 256。实际最高单题次为 2,996 Token。36 个题次共 **72 次调用、68,558 Token**，全部正常结束且返回用量。共发生 12 次交接，均在 Relay 组。实验前另有一次格式与计量连通性请求（45 Token），单独排除。该服务返回模型别名，没有固定权重版本。实验只调用模型服务进行推理，材料、依赖图和评分均在本地处理。

逐次记录包括模型返回的工作笔记、最终答案、请求摘要、用量和字段判分。重新评分可在构建仓库依赖后运行以下命令，无需模型凭据。[逐次记录](./trials.jsonl) · [模型、预算与数据指纹](./protocol.json)
