# GongYuAI 交付可信度与验收规划

2026-11-22。GongYuAI 面向真实生产委托。客户收到报告和证据包后，应能核对本次授权范围、每个目标的实际覆盖、仍然成立的结论，以及遗留事项由谁处理。工程回归使用可重复的虚构样本，生产交付验收使用获准用于本次验证的脱敏结项材料和独立人工底稿。

## 生产委托的结项标准

从现有控制台或 API 创建普通委托，写明约定目标、范围和排除项。交接时保存当时的范围与覆盖快照。结项时逐目标交代已做事项、证据、受阻原因和遗留项；有未履行事项时，报告记录负责人、后续安排或客户对范围变更的确认。任务结束、报告已交付、客户已确认分别留据。[现有生产交付入口和盲评方法](./evidence-review.md)

当前通用证据检查会仅凭文件名 `ALL_COMPLETE.json` 触发 TSecBench 清板校验，交付摘要也会依同名文件认定执行过内容检查。把这两个入口都列为验收对象。普通委托按其显式内容判据解释材料；基准样例按其显式规则做兼容回归。例如给一份只要求文件留存的普通委托提交同名业务附件，应按文件判据处理，两处结果一致。[证据检查](../packages/history/src/goal-evidence.ts) · [交付摘要](../packages/history/src/delivery.ts)

## 第一轮　目标究竟凭什么通过

假设一项委托同时核查甲、乙两套系统。甲有一条经过验证的发现，乙只有一份满足文件判据的检查记录。如果乙的目标明确要求确认一条发现，甲的发现不应让乙通过。如果乙的目标只是完成约定检查，材料足以证明覆盖时，应允许交付“在本次检查范围内未检出”。这两种目标在创建时就应该能区分。

当前工作区中，`assertGoal` 按任务取出全部发现，再按状态、严重程度和类别计数。读取计数发生在写事务开始之前，与契约里的“同一事务”有差异。既有测试确认已通过目标在发现撤回后保留首次通过记录。这里有两个独立问题，分别是首次判定用了谁的证据，以及该结论今天能否继续引用。[判定实现](../packages/history/src/index.ts) · [发现契约](../packages/contracts/src/finding.ts) · [既有测试](../packages/history/src/findings.test.ts) · [运行时契约](./long-run-contract.md)

### 建议的交付规则

1. **先声明目标的验收口径。** 对限定资产或目标的发现计数，保留支持该目标的 Finding ID、适用资产和证据版本。确实要求“全任务累计”的汇总目标可以显式采用任务范围。一条发现支持多个目标时，分别列出依据，每项目标内只计一次。
2. **给首次通过留下可以重算的依据。** 核对有效发现、写首次通过、固定所用证据应具有一致的提交顺序。撤回先提交，该发现不能参与首次通过；撤回后提交，保留首次通过与原依据，并在当前交付核对中标明变化。其他在断言前已备的独立证据仍足够时，当前结论可以继续成立；**归属在首次通过时冻结**，断言后新增的发现不会自动改写首次依据。
3. **分列历史通过、当前证据、实际覆盖。** 沿用现有已测、部分覆盖、受阻、未测和未知。零发现的报告写明范围、时间及未覆盖项。旧归档缺少目标关联时，保留原结果并标记“原依据归属未知”。相同地址、相似标题和相同文件名都不足以补历史归属。[覆盖快照与旧档读取](./evidence-review.md)
4. **F1 先定义分母。** 首版分别报“曾通过目标数 / 本次约定目标总数”“当前证据足以支持的目标数 / 同一总数”，旁列未知、受阻、撤回待复核项及统计时点。分母为零时写“不适用”。旧任务的未知项留在分母中单列，附范围版本后才能做跨期比较。发现准确率只使用有独立裁决的样本，同时公布已裁决数和待裁决数。[F1 现有设计](./data-flywheel.md)

### 工程回归

| 编号 | 给定材料或事件 | 读者应从交付物看到什么 |
| --- | --- | --- |
| A1 | 只有甲有合格发现。乙要求本资产至少一条，且乙自己的检查文件满足文件判据 | 甲通过，乙明确缺少与其关联的发现。显式声明全任务累计的汇总目标可以引用甲 |
| A2 | 乙改为覆盖型目标。分别提供完整覆盖材料、部分覆盖材料、缺失材料 | 三份结果能区分“本次范围内未检出”“仅覆盖所列部分”和“未知”。零发现自身不能证明覆盖 |
| A3 | 初次断言与撤回使用两个独立写入方，分别固定两种提交先后 | 撤回在先时首次断言失败；首次通过在先时，历史凭据可复验，当前交付提示唯一依据已撤回。另留一份独立有效依据时重新按门槛核定 |
| A4 | 只读打开一份已通过但缺少发现归属的旧档，重复生成两次记分卡 | 历史结果可查，当前归属未知；两次对同一快照的分子、分母一致，读取前后旧档字节一致 |
| A5 | 同一发现重复关联同一目标；另一个目标有独立理由复用这条发现 | 第一项目标只计一次；第二项目标可追查自己的依据。记分卡能从交付快照独立复算 |

工程交付包括 A1–A5、普通委托同名附件回归、基准兼容回归、构建结果和一份可独立复算的交付包。

### 生产交付验收

选一份已人工结项、已脱敏且获准用于本次验收的委托。保留材料出现的先后顺序、范围修订和中途交接点。由复核人事先封存预期结果，生成平台报告的一方只能使用截至当时可见的材料。在交接点和终态分别对照覆盖、未验证项、证据版本、已撤回结论和遗留事项。逐项记录一致、夸大、遗漏或证据不足，报告附回查位置。人工底稿只覆盖部分字段时，其他字段标为未验证。[已有覆盖快照及人工底稿对照](./evidence-review.md)

工程结果与生产盲评分列。缺少可用的真实归档或独立底稿时，继续完成工程交付，在交付单标记“生产盲评待验证”并列明缺件。记分卡用于核对覆盖和成本，结项仍按客户约定逐项判断。

| **已交付报告的更正** | 第一轮有稳定的目标与证据引用后做 | 报告第一版已交付，次日撤回一条被引用的发现。保留第一版及其摘要值，生成有编号的更正说明，列出受影响的报告版本、目标与已引用经验；有独立依据的结论单列。重复处理同一撤回只产生一份更正。操作员可区分“待通知”“已通知”和有凭据的“已确认收悉”。[报告复核](./evidence-review.md) · [记忆引用](./memory-layer.md) |
| **评测记忆隔离** | 在用飞轮结果宣称跨项目收益前完成 | 用冻结的记忆快照比较两组离线报告复核。两组只读同一初始快照，各自产出的历史和经验隔离。仅在留出样本中放一个唯一标记，调换两组运行顺序，确认另一组输入与历史查询均不可见该标记。单列“同项目复测”和“新项目首次交付”，记录人工底稿、快照摘要及实际读过的条目。[留出集纪律](./data-flywheel.md) · [盲评底稿](./evidence-review.md) |

一个需要单独保留的产品选择是“同资产时是否默认带入历史参考”。原聊天明确选择了自动、非阻塞展示历史接触，随后总纲将默认带入也记成定案。建议先自动展示，由操作员显式选择带入。未来若调整默认值，适用前提包括同委托、资产身份可核对、历史结论未撤回。这个选项不影响第一轮开工。[定调日志](./MASTER-DESIGN.md) · [面板设计](./memory-layer.md)
